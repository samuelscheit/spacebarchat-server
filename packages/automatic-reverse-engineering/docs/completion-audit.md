# Discord Datamining Automation Completion Audit

Objective: implement the pipeline described by `DISCORD_DATAMINING_AUTOMATION_PLAN.md` for action-scoped Discord Web datamining.

## Implemented Evidence

- Static snapshot collector: `collectDiscordStaticSnapshot` fetches `/login`, records build metadata, stores `login.html`, `build.json`, `assets.json`, downloaded assets, upstream and local hashes, discovered quoted JS/CSS chunks, and redacted durable source-map artifacts when present.
- Route catalogs: OpenAPI importer and Spacebar source-route importer generate `routes.catalog.json` and `routes.source.catalog.json`.
- Gateway catalogs: source importer generates opcode and Gateway event catalogs.
- Docs index: `build-docs-index` creates route/event/opcode reference links for official Discord docs and Userdoccers.
- Source ref resolver: `resolve-source-refs` records public GitHub commit SHAs for xHyroM and Userdoccers provenance.
- Experiment index: `extract-experiments` scans downloaded scripts for conservative experiment/rollout candidates.
- Third-party snapshot ingestion: xHyroM route and experiment snapshots, plus Userdoccers route and Gateway MDX snapshots, are imported into run-local static context files.
- Static context bundling: `bundle-static-context` copies selected route/Gateway/experiment/docs catalogs into a run's `static/` directory, writes `context.manifest.json` with safe relative paths plus hash/byte metadata, and merges source refs into `build.json`.
- Static scheduling: `.github/workflows/discord-datamining-static.yml` runs the public static pipeline on a 15-minute Canary schedule, an hourly PTB/stable schedule, and manual dispatch, including sparse checkouts of pinned xHyroM/Userdoccers refs plus static-only audit and allowlisted staged upload with raw `static/assets/` and `static/login.html` omitted.
- Fixture layer: fixture manifests can be generated as placeholder-only templates, fixture seed plans classify required resources as manual/official-API/browser-session/local-file setup, manifests are validated against scenario requirements, fixture values are resolved through `ctx.fixture(...)` inside scenarios, destructive-scenario disposable markers are validated, and redacted report-safe manifests preserve typed placeholders for guilds, channels, roles, users, messages, applications, emojis, stickers, and files.
- Runtime preflight: `preflight-runtime` validates fixture requirements, disposable fixture markers, Playwright storage-state presence, storage-state freshness from an explicit capture timestamp or local file mtime fallback, and expired Discord auth-cookie evidence without copying or printing session values or raw storage-state filesystem paths; `audit-run` rejects malformed, stale, expired, or inconsistent durable preflight reports before accepting runtime artifacts; `--all-built-ins true` emits a full-suite readiness report with aggregate fixture requirements and a placeholder-only fixture template.
- Runtime capture: `CdpNetworkRecorder` records HTTP lifecycle, request/response body shapes and redacted samples, sanitized CDP initiator stack frames/hashes, CDP extra-info headers, WebSocket creation/handshakes/frames/errors/closes, step markers, redacted UI action labels, and redacted Gateway payload samples.
- Browser artifact wrapper: `runPlaywrightCapturedFeature` records step screenshots, optional local trace ZIPs, explicit video, CDP events, and Playwright page-level HTTP/WebSocket convenience events through Playwright-shaped interfaces without adding Playwright as a package dependency.
- Browser runtime command: `run-playwright-feature` dynamically imports optional Playwright, preflights storage state/fixtures, runs built-in scenarios only, navigates via fixture IDs, keeps fixture-scope enforcement on by default, annotates summaries/reports with run-local static candidates when static assets are present, retains video for failed scenarios by default, records raw HAR only under an OS temp directory before writing sanitized HAR output, removes temporary raw HAR/video files, and writes only closed-shape feature-local slash-relative paths into failure/run-artifact manifests.
- Mitmproxy secondary validation: `import-mitmproxy` converts local mitmproxy JSON flow exports into redacted `mitmproxy.redacted.ndjson` HTTP/WebSocket evidence plus an optional count summary, while keeping raw dumps out of durable run output.
- Manual runtime smoke workflow: `.github/workflows/discord-datamining-runtime-smoke.yml` is `workflow_dispatch` only, keeps storage state and fixture secrets under `$RUNNER_TEMP`, requires an explicit storage-state capture timestamp so decoded secret mtime cannot mask stale sessions, writes a non-blocking full-suite `runtime-readiness.json`, runs one built-in scenario after static collection, generates coverage and review queue artifacts, gates upload on redaction and completion audit including coverage/review checks, and stages only explicitly allowlisted redacted text/HAR artifacts with an `upload-manifest.json` whose `uploaded_files` list is computed from the final staged tree and whose `audit_scope` marks completion audit as runner-local; raw `static/assets/`, `login.html`, trace, screenshots, and videos are omitted from upload.
- Redaction gate: `NdjsonEventWriter` refuses likely secrets and unsafe UI action labels at write time, and `validate-redaction` audits JSON/NDJSON/Markdown/text/HAR/SQL/Source Map artifacts offline, including raw email and snowflake-looking ID detection plus structured rejection of raw Playwright storage-state JSON. CI upload steps omit raw static HTML/JS/CSS and binary artifacts because those are outside the text redaction audit surface.

- Runtime safety gates: destructive scenarios require disposable fixture markers before runtime starts; rate-limit, CAPTCHA, and checkpoint signals emit `runtime.abort`, mark the run for quarantine, write redacted failure artifacts, and throw `CaptureAbortError`.
- Correlation/reporting: feature summaries preserve expected traffic metadata, step titles, redacted UI action labels, traffic shape hashes, and compact redacted request/response/payload samples, with repeated same-route HTTP observations paired by request ID when available; markdown feature reports render the ordered action sequence with build context, redacted fixture context, docs links, static candidates, and experiment/feature-flag candidates, route coverage with build history/catalog annotations, Gateway coverage with build history/catalog annotations, JSON and Markdown feature diffs, JSON and Markdown build diffs, review queues including custom-scenario expectation failures, runtime failure review items, shape/timing-aware aggregate background-noise suppression, and static candidate annotation are implemented. - Local query index: `export-sqlite-index` emits a SQLite-compatible SQL export for runs, features, steps, HTTP observations, Gateway observations, payload shapes, route catalog rows, Gateway catalog rows, and static candidates without adding a native database dependency.
- Built-in scenarios: 26 scenarios are registered across bootstrap, navigation, messages, read state, threads, search, member discovery, expressions, guild/channel settings, voice, and experiments, with registry invariant tests for scenario IDs, destructive safety metadata, disposable fixture declarations, expected evidence metadata, expected-evidence step IDs, and run-specific content for non-destructive message-creating scenarios.
